Repositories en cloning

Basis van Git & Projecten importeren
Nog niet gedaan

Wat leer je in deze les?

Je leert hoe je een nieuw project start in Git en een bestaand project van GitHub naar je eigen computer ophaalt.

  • Git Repository: De centrale map waarin Git al je wijzigingen en bestandsgeschiedenis bijhoudt.
  • git init: Maakt van een gewone map een Git-repository op je computer.
  • git clone <url>: Downloadt een kopie van een remote GitHub-project inclusief alle geschiedenis naar jouw lokale pc.
# Een repository klonen naar je computer
git clone https://github.com/gebruiker/project-naam.git

Branches en merging

Veilig experimenteren in aparte vertakkingen
Nog niet gedaan

Wat leer je in deze les?

Met branches kun je aan een nieuwe functie (feature) werken zonder dat je de werkende code in de hoofdbranch (main) verstoort.

  • Branching Strategy: Werken met een main branch voor stabiele code en feature-branches voor updates.
  • git branch feature-naam & git checkout feature-naam: Maak en wissel naar een nieuwe branch.
  • git merge feature-naam: Voeg de goedgekeurde code uit je branch samen met de main branch.
git checkout -b feature/nieuwe-pagina
git commit -m "Voeg nieuwe pagina toe"
git checkout main && git merge feature/nieuwe-pagina

Pull requests en code review

Kwaliteitscontrole & Feedback vragen
Nog niet gedaan

Wat leer je in deze les?

Een Pull Request (PR) is een verzoek aan je teamgenoten of docent om jouw voorgestelde code-wijzigingen te bekijken en goed te keuren.

  • Pull Request maken: Vergelijk je branch met de main branch op GitHub.
  • Code Review: Inline commentaar achterlaten bij specifieke regels code om fouten op te sporen.
  • Approvals & Merging: Pas wanneer een reviewer akkoord geeft, mag de PR gefuseerd worden met de hoofdcode.

Issues en projectbeheer

Bugs bijhouden, taken verdelen & Kanban
Nog niet gedaan

Wat leer je in deze les?

Ontdek hoe je met GitHub Issues en Projects taken plant, bugs registreert en de voortgang van het team visueel opvolgt.

  • Issues: Rapporteer een bug of vraag een nieuwe functie aan.
  • Labels & Assignees: Koppel een verantwoordelijke leerling en categorieën toe (bv. bug, enhancement).
  • GitHub Projects: Werken met een Kanban-bord (To Do, In Progress, Done).

.gitignore en best practices

Gevoelige data uitsluiten & Schone repo's
Nog niet gedaan

Wat leer je in deze les?

Niet alle bestanden horen op GitHub thuis! Denk aan wachtwoorden, tijdelijke bestanden of zware installatiemappen.

  • .gitignore bestand: Specifiek tekstbestand met patronen van bestanden die Git moet negeren.
  • Veiligheid: Voorkom het lekken van API keys, wachtwoorden en .env bestanden.
  • Grote bestanden: Negeer mappen zoals node_modules/ of build-bestanden.
# Voorbeeld inhoud van .gitignore
node_modules/
.env
*.log

Samenwerken in teams

Collaborators, rollen en team workflows
Nog niet gedaan

Wat leer je in deze les?

Samen aan één project bouwen vereist goede afspraken. Leer hoe je klasgenoten toegang geeft tot je repository.

  • Collaborators toevoegen: Klasgenoten uitnodigen via hun GitHub gebruikersnaam.
  • Toegangsrechten: Verschil tussen Read, Write en Admin permissies.
  • git pull: Altijd de nieuwste wijzigingen van je teamgenoten ophalen voordat je zelf begint te coderen.

Conflicten oplossen

Merge conflicts begrijpen en verhelpen
Nog niet gedaan

Wat leer je in deze les?

Wanneer twee personen dezelfde regel code aanpassen, ontstaat een Merge Conflict. Geen paniek! Je leert dit stapsgewijs oplossen.

  • Conflict markers herkennen: Begrijp de symbolen <<<<<<<, =======, en >>>>>>>.
  • Oplossen in VS Code: Kies tussen 'Accept Current Change', 'Accept Incoming Change' of voeg beide samen.
  • Afronden: Sla het bestand op, maak een nieuwe commit en push je opgeloste code.

GitHub Pages, CI/CD & Portfolio opbouwen
Nog niet gedaan

Wat leer je in deze les?

In deze slotles ontdek je hoe professionele ontwikkelaars en IT-bedrijven GitHub inzetten voor hosting en automatisering.

  • GitHub Pages: Zet jouw HTML/CSS/JS websites gratis live op het internet.
